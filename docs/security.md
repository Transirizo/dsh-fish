# 安全：实际状态与目标分开记录

## 已实现（源码/单测）

- /say 只接受 simulation 事件；真实平台模式拒绝；诊断 Agent 禁止全部模型工具。见 [验证报告](say-verification.md)。
- 模型可调用的记忆工具必须携带 exec.agent；写入范围由宿主决定，默认 session:<id>。不接受模型把范围提升为 global/shared。
- 召回、日记、兴趣读取按调用者过滤；状态工具不暴露磁盘路径或其他会话的记忆条数。
- 秘密模式拦截是启发式补充，不是隐私分类或提示注入防御的充分证明。
- 联网默认拒绝：没有宿主注入的受限抓取代理时，fish_browse/browse 不回退系统 fetch。

## 部分实现，不可据此开放真实平台

- delivery.js 只是独立授权逻辑，尚未形成与真实平台适配器连接的完整发送链；静默时段、持久审计、跨部署单活仍需验收。
- JSONL 记忆工具已按调用者限制，但历史 global/shared 数据、内部反思、备份导出、删除与提供方传输仍需统一范围策略。
- URL 静态校验与预算不是完整 SSRF 防护。DNS 重绑定、地址绑定、网络出口限制未验证。
- 单个模型工具 guard 不等于操作系统、文件、网络和管理服务隔离；生产 GUI 当前工程/聊天身份未严格分离。

## 生产与源码区别

生产插件已安装启用不表示最新源码已经进入运行时。没有模块 watcher 的情况，应在隔离测试后按受控更新/重启流程加载，并重新检查当前 GUI 与接口。

整改任务见 [SEC-01](plans/security-boundaries.md)。
